## Контекст проекта

Мы делаем EduTask — MVP для образовательного трека. Преподаватель описывает педагогическую проблему, AI задаёт уточняющие вопросы, создаёт карточку задачи, рассчитывает рейтинг готовности и публикует задачу в каталоге. Студенческие команды отправляют предложения, преподаватель вручную выбирает команду.

Команда состоит из 3 человек. Моя роль — Backend + API + Demo.

## Критический сценарий MVP

1. Сырое описание задачи.
2. Минимум 3 уточняющих вопроса.
3. Формирование редактируемой карточки.
4. Рейтинг от 0 до 100.
5. Публикация в каталог.
6. Отправка предложения команды.
7. Ручное принятие или отклонение предложения.

## Текущий стек и структура

- HTML/CSS/JavaScript без фреймворка;
- Node.js;
- Backend: `api/server.js`;
- рейтинг: `api/scoring.js`;
- схема карточки: `api/task-schema.json`;
- API-документация: `docs/api-contract.md`;
- демо-данные: `data/tasks.json`;
- запуск: `npm.cmd start`.

## Текущий статус

- Backend запускается на `http://localhost:3000`;
- работают health-check, создание черновика и каталог;
- добавлены mock-endpoints генерации карточки, публикации и предложений;
- AI API ещё не подключён;
- Frontend пока частично работает на локальной логике.

## Правила работы

1. Перед изменениями сначала осматривай текущие файлы и не переписывай существующий код без необходимости.
2. Двигайся маленькими этапами.
3. Если задача связана с кодом — сначала дай краткий план, затем реализуй его.
4. Используй `apply_patch` для изменений файлов.
5. Не используй опасные команды и не удаляй пользовательские файлы.
6. После изменений проверяй JSON, синтаксис и `git diff --check`.
7. Если Node.js или другая утилита отсутствует, предложи рабочую альтернативу.
8. Не усложняй архитектуру: приоритет — работающий MVP и демонстрация.
9. API-ключи никогда не помещай во Frontend; используй `.env`.
10. AI должен возвращать структурированный JSON и не выдумывать данные.
11. Если API недоступен, сохраняй локальный fallback.
12. Не делай регистрацию, оплату, real-time чат, мобильное приложение или сложную ML-модель.

## Формат каждого ответа

- затем перечисли изменённые файлы;
- затем дай команды запуска и проверки;
- отдельно напиши, что осталось сделать;
- если возник блокер, предложи самый быстрый рабочий обходной путь.

За минимальное время довести проект до стабильного MVP, который можно запустить по README и показать за 5 минут — от ввода сырой задачи до принятия предложения студенческой команды.
